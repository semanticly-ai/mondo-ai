# mondo-ai — System Specification

Status: as-built, reflecting the repository state on the `main` branch after the
SIEVE/SEPIO datamodel consolidation. This document mirrors what the code does
today, not what it aspires to. Where a capability is partial or a gap exists, it
is called out in [Known limitations](#known-limitations).

## 1. Purpose

mondo-ai is an evidence-driven pipeline for curating and QA-ing content in the
[Mondo](https://mondo.monarchinitiative.org/) disease ontology. It extracts
candidate assertions (synonyms, subclass relations, definitions) from source
ontologies, translates them into Mondo space via SSSOM mappings, packages each
assertion with typed evidence and provenance, scores the evidence, and
optionally enriches it with literature and AI synthesis. Output is a store of
**evidence packets** ready for curator review.

The evidence model is built on **SIEVE** (the local evidence framework, sourced
from the sibling `../sieve` package) layered on **SEPIO** (Scientific Evidence
and Provenance Information Ontology). Models are defined in LinkML and compiled
to Pydantic v2.

## 2. Technology stack

- **Python** ≥ 3.10, < 4.0 (pinned to 3.11 via `.python-version`)
- **uv** for dependency management, **just** as the command runner
- **LinkML** + `linkml-runtime` for the schema; `gen-pydantic` generates the models
- **Pydantic v2** for the runtime datamodel
- **pyoxigraph** for RDF/OWL parsing
- **Typer** for the CLI; **FastAPI** + **Jinja2** + **uvicorn** for the web browser
- **pydantic-ai** for AI synthesis (Anthropic or OpenAI)
- **SQLite** (stdlib) for the queryable packet index
- **pytest** / **mypy** / **ruff** for testing, typing, and linting

## 4. Data model (SIEVE/SEPIO)

The datamodel is generated by `gen-pydantic` into
`src/mondo_ai/datamodel/sieve_models.py` from the LinkML schema in
`src/mondo_ai/schema/`:

- `mondo_ai_sieve.yaml` — root schema, imports the SEPIO classes
- `sepio_classes.yaml` — trimmed SEPIO subset actually used
- `sepio_classes_full.yaml` — full SEPIO reference
- `sieve_sepio.yaml` — SIEVE + SEPIO base

Public classes are re-exported from `mondo_ai.datamodel` (`__init__.py`).

### Packet structure

```
EvidencePacket
├── id                       deterministic (pkt_<hash>)
├── statement: SieveStatement
│   ├── subject / subjectLabel      Mondo term (e.g. MONDO:0005015)
│   ├── predicate: Coding           OWL predicate as a SEPIO Coding
│   ├── object / objectLabel        synonym text, parent term, etc.
│   └── statementText
├── hasEvidenceLines: [SieveEvidenceLine]
│   ├── hasEvidenceItems: [InformationEntity subclass]
│   │     ConcordanceItem | SieveDocument | SieveDataItem |
│   │     SieveStudyResult | ComputationalResult | AgentContribution
│   ├── directionOfEvidenceProvided   supports | disputes | neutral
│   ├── strengthOfEvidenceProvided    strong | moderate | weak
│   └── scoreOfEvidenceProvided       float
├── evidence_synthesis: EvidenceSynthesis | None   (score, direction, summary)
├── status: CurationStatus            UNREVIEWED (default), ACCEPTED, REJECTED, …
└── created / updated
```

### Key enums

`CurationStatus`, `EvidenceDirection` (supports/disputes/neutral),
`EvidenceStrength` (strong/moderate/weak), `EvidenceItemType`, `TrustLevel`
(community/domain_expert/curator/authority), `ContributionType`
(suggestion/review/decision/provision), `ContributionChannel`, `StatementPredicate`
(EXACT/NARROW/BROAD/RELATED synonym, LABEL, DEFINITION, PARENT), `SynonymScope`,
`RecommendedAction` (ADD/CONFIRM/REJECT/REVIEW).

### Provenance

`AgentContribution` records who/what asserted something with a `TrustLevel`:
Mondo consortium membership (organizational decision, `authority`), ORCID-tagged
expert determinations (`curator`), and candidate literature (PMIDs found in source
annotations, weak strength). ORCIDs/PMIDs are parsed from annotation source
strings during extraction.

`loaders.py` handles polymorphic deserialization — evidence items are dispatched
to the correct subclass by their `type` field. `mappings.py` converts between
`StatementPredicate` enums and SEPIO `Coding` objects.

## 5. Pipeline

`PipelineRunner` (`pipeline.py`) runs the end-to-end flow. Inputs: a
`mondo.sssom.tsv` mapping file and OWL files for OMIM, ORDO, DOID (and optionally
Mondo). Stages:

1. **Extract** — `OWLExtractor.extract()` parses each OWL file with pyoxigraph and
   yields a `ResourceSnapshot` of `EntitySnapshot`s (labels, synonyms with scope,
   parents, provenance), filtered by IRI prefix (e.g. `DOID_`, `omim.org/entry/`)
   and skipping deprecated terms.
2. **Map** — `SSSOMReader` translates each source ID to its Mondo ID; entities
   without a mapping are dropped.
3. **Build statements** — synonyms and `rdfs:subClassOf` relations become
   Mondo-space `SieveStatement`s with deterministic SHA256-based IDs.
4. **Build packets** — `PacketBuilder` wraps each statement in an `EvidencePacket`
   with a `SieveEvidenceLine` carrying a `ConcordanceItem` (cross-source match),
   weighted by per-source reliability (OMIM 0.95, ORDO 0.90, DOID 0.85).
5. **Score** — `Scorer.score_packets()` computes the NER for each packet.

`MondoExtractor` is a Mondo-specific extractor that additionally builds
consortium/expert/candidate-literature evidence lines (see
[Known limitations](#known-limitations) for how this evidence currently reaches —
and does not reach — packets).

## 6. Scoring and synthesis

**Scoring** (`scoring/scorer.py`). The Net Evidence Ratio is

```
NER = (S⁺ − S⁻) / (S⁺ + S⁻ + S⁰)          range [-1, +1]
```

where S⁺/S⁻/S⁰ are the summed `scoreOfEvidenceProvided` over supporting /
disputing / neutral evidence lines. Recommendation thresholds (configurable):
NER ≥ 0.7 → ACCEPT, NER ≤ −0.3 → REJECT, otherwise REVIEW. Per-source,
per-content-type weights come from `ContentWeights` in the config.

**Synthesis** (`agents/synthesis.py`). `SynthesisAgent` uses pydantic-ai to
produce a `SynthesisResponse` (action, confidence, summary, key_evidence),
attaches an `EvidenceSynthesis` to the packet, and records a `CurationActivity`.
Providers: Anthropic (default) or OpenAI, selected via config; requires
`ANTHROPIC_API_KEY` / `OPENAI_API_KEY`.

**Enrichment** (`enrichment/`). `PacketEnricher` + `PubMedClient` add
`SieveDocument` literature evidence. Incremental by default (`skip_enriched=True`
skips packets that already carry literature evidence); the CLI `--force` flag
re-enriches. References are cached locally.

## 7. Storage

**JSONL store** (`storage/jsonl_store.py`) — the primary, distribution-oriented
backend. Packets are appended to `packets_NNN.jsonl` files. A file is **sealed**
(made immutable) once it crosses the soft size limit (default 50 MB); exceeding
the hard limit (90 MB) is an error. A `manifest.json` tracks file metadata and a
`index.json` maps `packet_id → PacketLocation` (file, offset, length) for O(1)
retrieval.

**SQLite index** (`storage/index.py`) — `PacketIndex` builds a queryable table
(`subject_id`, `predicate`, `status`, `score`, `evidence_count`, `source_ids`, …)
with indexes on subject/status/score/predicate, for fast filtering without loading
full packets.

## 8. Configuration

`config.py` defines `PipelineConfig` (loadable via `PipelineConfig.from_yaml`)
composed of: `ResourceConfig` per source (id/name/url, `enabled_content`,
per-source `ContentWeights`), `ScoringConfig` (accept/reject/review thresholds),
`EnrichmentConfig` (PubMed settings), `AgentConfig` (provider/model),
`StorageConfig`, and `JSONLStorageConfig` (store dir, `max_file_size_mb`).
`mondo-ai init-config` writes a sample config.

## 9. CLI

Typer app (`cli.py`), invoked as `mondo-ai <command>`. 23 commands:

| Group | Commands |
|-------|----------|
| Pipeline | `run`, `download`, `extract` |
| Packets | `build-packets`, `build-packets-multi` |
| Scoring / enrichment / AI | `score`, `enrich`, `synthesize` |
| Index & query | `index`, `query`, `index-stats` |
| Show / export / validate | `show`, `export`, `validate` |
| JSONL store | `jsonl-export`, `jsonl-stats`, `jsonl-get`, `jsonl-rebuild-index`, `jsonl-browse`, `jsonl-load` |
| Utilities | `extract-owl`, `init-config`, `stats` |

Note: `index-stats` reports on the SQLite index; `stats` reports on a packet
collection. (These were previously both named `stats`; the index variant was
renamed to resolve the collision.)

## 10. Web browser

`web/app.py` — a FastAPI app over the JSONL store, run with `just serve-web`
(`uvicorn mondo_ai.web.app:app`). Routes:

- `GET /` — dashboard with summary statistics
- `GET /packets` — filterable, paginated packet list (by source, predicate, status)
- `GET /packets/{packet_id}` — packet detail
- `GET /api/stats` — statistics JSON

The store and computed stats are lazily loaded and cached as module singletons.
Templates live in `web/templates/`.

## 11. Testing and tooling

`just test` runs `pytest`, `doctest`, `mypy`, and `ruff` — currently **green**:
230 tests passed / 3 skipped (skips need AI API keys or an external SSSOM file),
31 doctests passed / 1 skipped, mypy clean across 45 source files, ruff clean.

Other recipes: `just pytest`, `just doctest`, `just mypy`, `just format`,
`just gen-pydantic` (regenerate `sieve_models.py`), `just run-pipeline`,
`just serve-web`, plus grouped acquisition/extraction/build/validate/score/enrich
recipes in `project.justfile`.

The interpreter is pinned via `.python-version` (3.11) and the package ships a
`py.typed` marker (PEP 561). `sieve_models.py` is generated code and is excluded
from type-checking via `mypy.ini`.

## 12. Known limitations

Open threads tracked in `todo.md`:

- **Low subclass axiom counts** — DOID yields 16,564 `subClassOf` packets, expected
  to be more; investigate `_extract_hierarchy` filtering and SSSOM/IRI-filter
  coverage.
- **Journal-quality signal for scoring** — whether to weight literature evidence by
  journal impact or a similar metric (open design question).

`MondoExtractor` (Mondo-native extraction with consortium/expert/literature
provenance via `extract_mondo_with_evidence`) is exercised only by tests; it is not
yet wired into `PipelineRunner`, which currently builds evidence for OMIM/ORDO/DOID
through `OWLExtractor`. Integrating the Mondo path into the pipeline is a future step.
